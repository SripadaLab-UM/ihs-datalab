# 0.3.0-beta.2: packaged-app acceptance (Mac, practice)

Tested 2026-09-29 on the maintainer's Mac (Apple silicon, macOS 26), with the
**released** 0.3.0-beta.2 files and the real installer. The profile was
practice only, with synthetic data. The model was gpt-5.5 on U-M GPT, using
the key the real DataLab had saved. The release files' SHA-256 sums matched
`SHA256SUMS`.

Real-data (production Oracle 19c) and Windows runs aren't part of this record.
The Windows checklist below is for the Windows tester.

## Findings (queued for the next release)

1. **The installer's finish reads like a failure.** Pressing Ctrl-C at the optional "Show DataLab (practice) in Finder? [Y/n]" question, after the install has finished, prints "Stopped. Run this installer again when you are ready…". After "Done" it should just end.
2. **Ctrl-C on `datalab serve` prints a Python `KeyboardInterrupt` traceback.** It stops cleanly otherwise; it should print one line ("DataLab stopped.").
3. **On practice, the agent's attempts to read the knowledge base count as failed steps.** Practice has no knowledge base copy, so "Read AGENTS.md" and "Read index.md" fail, and the answer's checks list "4 failed steps … 3 unresolved". Either practice should tell the agent there is no knowledge base, or those reads shouldn't be reported as unresolved failures.
4. The toolbar's "Database: synthetic, not tested yet" didn't update after a connection test run through the API (not through its own button). This is minor, and possibly by design.

## Windows checklist (for the Windows tester, on 0.3.0-beta.2)

Update from the app (Settings → Updates), or install with
`install-windows.ps1 -Practice` from the release. Then:

1. **Launch and connect:** Settings → Connections → Test connection gives "Connected, read-only" and U-M GPT accepted.
2. **Ask** an Analysis question on practice. Approve the plan and get an answer with its checks.
3. **Failure shown:** ask for "the average of 1/0 over the 2025 participants" (or anything that fails). The failed step must show the reason and ORA code ("the database refused it: …"), and "recovered" once a later query works. In 0.3.0b1 it showed no reason.
4. **Export** the conversation plus an output to an export folder, and check the dated folder.
5. **Restart** DataLab and check the conversation is intact.
6. **Updates:** Settings → Updates shows the hourly-check checkbox and "Last checked …".
7. **Express:** switch it on and ask a quick count. Expect no plan, a fast answer and an "Express" tag.
8. **Pickers** (0.2.0b7): the export-folder and attach-file dialogs open in front of the browser.
9. **Catalog on real** (0.2.0b6): column-based SQL works without `catalog_dir`.
10. Report anything that differs, with **Copy diagnostics** (Settings → About).
